# Минимизация записи на носители (SD/eMMC)

Проблема: постоянные записи (БД, логи) убивают карты за месяцы.
На практике: SD-карта X96 Max и SD Orange Pi вышли из строя.

## Правила

1. **devices.db — только на HDD.** Скрипт `deploy/setup_hdd_db.sh`
   переносит БД в `/srv/lan-discovery/`, оставляет симлинк
   `/opt/lan-discovery/devices.db` и ставит drop-in юнита
   `Requires=srv.mount`: без смонтированного диска панель **не стартует**,
   чтобы БД не создалась заново на корне (SD/eMMC).
2. **Логи — в tmpfs/zram.** На Orange Pi `/var/log` на zram,
   `/tmp` — tmpfs (во fstab). Journald — в памяти.
3. **Системный корень — без лишних записей.** Скрипты/каталоги
   `/opt/lan-discovery` не содержат постоянно растущих файлов
   (проверка: `find /opt/lan-discovery -mtime -1`).
4. **HDD подключён всегда** (fstab: `nofail`, монтируется в `/srv`).

## Проверка

```bash
# что реально пишется на корень за сутки
find /opt/lan-discovery /var /tmp -newer /opt/lan-discovery/devices.db -type f
# БД на диске?
ls -la /opt/lan-discovery/devices.db   # -> /srv/lan-discovery/devices.db
mount | grep /srv
```
